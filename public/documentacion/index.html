Visión General del Ecosistema VectorLab

VectorLab no es solo un punto de venta, es un sistema de Planificación de Recursos Empresariales (ERP) interconectado. El flujo de la información está diseñado para que cada acción de un usuario en un módulo alimente automáticamente las estadísticas, inventarios y finanzas del resto del sistema en tiempo real.

En un nivel macro, el sistema cuenta con varios submódulos altamente especializados. El Módulo de Inventario actúa como el núcleo de operaciones y de datos físicos, proveyendo al Cotizador (Fórmulas) con los costos reales de los materiales, y a su vez, entregando mercancía lista para ser vendida en el Punto de Venta (POS). Finalmente, todas las salidas de inventario y entradas de dinero se concilian en el módulo de Arqueos / Gastos Operativos para ofrecer reportes de rentabilidad.

1. Búsqueda y Navegación Inteligente del Inventario

La eficiencia operativa de un almacén comienza por encontrar el producto correcto en cuestión de segundos, incluso cuando la base de datos almacena miles de SKU. Hemos eliminado por completo el proceso arcaico de "escribir un nombre, presionar un botón de buscar y esperar a que la página recargue". Nuestro motor asíncrono se activa desde el primer carácter que el usuario teclea, optimizando el tiempo de respuesta y eliminando la frustración del empleado y del cliente que espera en mostrador.

Mecánicas de Experiencia del Usuario (UX)

  • Búsqueda Global Multidimensional: Al teclear, el algoritmo no solo revisa el nombre comercial, sino que examina simultáneamente los Códigos de Barras y los Códigos Internos (SKU). Esto permite al usuario buscar un artículo utilizando un lector láser o escribiendo a mano.
  • Filtrado Especializado por Marca/Proveedor: El filtro de "Proveedores" permite aislar visualmente toda la mercancía suministrada por una marca específica. Esto es esencial para los gerentes que necesitan hacer inventarios físicos rápidos de una sola marca antes de recibir a un representante de ventas o distribuidor.
  • Radar Crítico de Desabasto: Con el encendido de un interruptor "Ver Faltantes", el sistema despliega una lista de emergencia de mercancía que ha tocado su "Stock Mínimo". Este interruptor elimina la necesidad de revisar hoja por hoja qué comprar, entregando un reporte instantáneo para generar órdenes de compra al momento.

2. Ciclo de Vida del Producto (Alta y Edición)

Hemos eliminado la necesidad de tener múltiples pestañas abiertas. La captura de un nuevo producto, que tradicionalmente requiere navegar entre menús para crear marcas y clasificaciones, ahora se realiza en un único mega-formulario ergonómico. Si el capturista advierte que olvidó registrar un Proveedor de antemano, el sistema cuenta con "Botones de Creación Inline" que pausan el formulario, permiten crear al proveedor en una ventana secundaria, y devuelven al usuario a su trabajo sin perder una sola letra de lo que ya había escrito.

Anatomía de la Creación Comercial

  • Identidad y Trazabilidad: Nombre comercial exacto, Código Único de registro, y las relaciones vitales (Categoría y Proveedor). Esta información es la que el cliente verá en su ticket de compra.
  • Motor Financiero y de Rentabilidad: Se capturan los Costos base (sin IVA o con IVA según configuración) y los Precios de Venta (Público general y Mayoreo). El módulo financiero utilizará esta brecha entre Costo y Precio de Venta para proyectar las utilidades netas del negocio en tiempo real.
  • Configuración Logística y Alarmas: Se establece un "Stock mínimo" que determinará en qué momento el producto cambia de color a rojo en la tabla. Además, se pre-configura cómo llega empaquetado este artículo (Unidades sueltas, por Paquetes, o en Cajas Master), preparándolo para hacer los futuros ingresos de mercancía en segundos.

3. Calculadora de Surtido Logístico Automática

Un problema recurrente en el retail es la merma por errores humanos al sumar inventario. Atrás quedaron los días de contar cajas en el piso, multiplicarlas en una calculadora de bolsillo y luego teclear el resultado final en la computadora. Esta herramienta logística convierte la recepción de mercancía en un proceso automatizado y a prueba de errores, traduciendo formatos de empaque industriales a unidades de venta de forma instantánea.

Mecánicas de Inserción Acelerada

  • Surtido al Detalle (Simple): Cuando la mercancía se recibe suelta en bolsas o por pieza. El usuario simplemente digita la cantidad recibida y el sistema hace una suma plana.
  • Surtido Empaquetado (Medio Mayoreo): Para mercancías agrupadas en empaques cerrados (Ej. Six-packs de refrescos o Tiras de papas). El usuario digita cuántos paquetes físicos llegaron y el sistema le pregunta cuántas piezas tiene un paquete. La multiplicación corre en segundo plano.
  • Surtido Industrial (Volumen): Ideal para Pallets y compras al por mayor. El usuario detalla que llegaron 10 Cajas, y que cada Caja contiene 24 Paquetes, y que cada Paquete contiene 2 piezas. El motor logístico realiza la ecuación de tres variables en tiempo real, previniendo descuadres de cientos de piezas por equivocaciones aritméticas en la cabeza del almacenista.

4. Centro de Comando de Categorías Unificado

Hemos unificado lo que antes requeriría tres pantallas distintas de configuración en una sola ventana flotante ultra veloz. Los administradores pueden gestionar la clasificación general del sistema sin perder de vista su tabla de inventario que permanece en el fondo. Además, permite un manejo masivo de la información mediante eventos de teclado para usuarios avanzados.

Seguridad Anti-Orfandad (Prevención de Pérdidas)

En sistemas ERP deficientes, si un empleado elimina una categoría (por ejemplo, "Herramientas de Jardín"), todos los productos ligados a esa categoría pueden corromperse o desaparecer de la base de datos de forma silenciosa. En VectorLab hemos implementado un Seguro Anti-Orfandad. Si se elimina una categoría, el sistema detecta qué productos dependían de ella y los migra de forma segura y automática a una categoría predeterminada (Ninguna / General). Esto salva el capital del cliente y previene auditorías fallidas.

Características Especiales y UX

  • Creación "Inline" a la Velocidad de la Luz: Un campo de texto fijado siempre en la parte superior. Funciona como la barra de un chat: escribes "Abarrotes" y presionas la tecla `Enter`. La categoría se crea, la lista se refresca instantáneamente y la ventana de éxito dura milisegundos para permitirte seguir trabajando, sin molestas validaciones que interrumpan el flujo.
  • Propagación en Cascada: Si cambias el nombre de "Lacteos" por "Lácteos (Refrigerados)", el sistema actualizará en tiempo real ese nombre en los miles de productos que lo utilizan sin que el usuario tenga que hacer ningún proceso masivo complejo.

5. Comunicación B2B y Canales de Exportación Directa

Hemos transformado un simple botón de "Generar PDF" en una poderosa herramienta omnicanal de ventas. Un gran dolor de cabeza administrativo es tener que descargar un archivo, guardarlo en el escritorio, abrir Outlook, redactar un correo, buscar el archivo y enviarlo. En VectorLab, el reporte legal generado por el sistema se inyecta directamente a los canales de comunicación del cliente en milisegundos.

Vías de Distribución Corporativa Incorporadas

  • Personalización Quirúrgica (Checkboxes): El usuario tiene el control total de la información. Puede generar un catálogo con los 15,000 artículos para uso interno contable (dejando todas las casillas sin marcar), o puede marcar manualmente con una "palomita" solo 5 productos específicos para armar una cotización y enviársela de forma privada a un cliente sin revelar el resto de su inventario.
  • Navegador Nativo (Para Impresión Física): Abre el documento directamente en una nueva pestaña listo para enviarse a la impresora física para colgarse en el almacén o firmarse.
  • WhatsApp Business API: Requiere solo un clic. Abre un chat directo en WhatsApp Web o en la aplicación móvil de PC con el número predefinido del cliente. Adjunta automáticamente un mensaje de cortesía profesional e inyecta la URL del PDF del sistema (o el documento mismo) listo para enviar.
  • Email Server (Envío Transparente): Utiliza el servidor SMTP central de VectorLab. Pide el correo destino, y en segundo plano despacha un email elegante con membrete de la empresa y adjunta el PDF sin que el usuario tenga que salir jamás del inventario.

6. Anexo Técnico: Manual de Desarrollo y Personalización

Esta sección es de carácter ESTRICTAMENTE TÉCNICO. Está dirigida a Ingenieros de Software, Arquitectos y Equipo de Ventas Técnicas de VectorLab.

El propósito de este manual profundo es que el desarrollador pueda tomar el código fuente y modificarlo, alterarlo o escalarlo para adaptarlo a flujos de trabajo de clientes corporativos complejos sin romper la lógica asíncrona existente.

6.1. Stack Tecnológico General

El sistema renuncia al enfoque de API REST con React/Vue en favor de un enfoque de Server-Side Rendering (SSR) con hidratación dinámica para reducir la carga cognitiva del lado del cliente y facilitar el SEO interno. Los componentes clave son:

  • Backend: PHP 8.2+ orquestado sobre Laravel Framework 11.
  • Motor Reactivo: Laravel Livewire (v3). Se encarga de hacer el "Data Binding" entre el servidor y el navegador mediante llamadas XHR / fetch invisibles.
  • Renderizado (View Layer): Laravel Blade Templates.
  • Estilización Rápida: Tailwind CSS. Funciona mediante utilidades de clase atómicas.
  • Interactividad y Flujos Modales: Vanilla JavaScript en conjunción con la librería SweetAlert2 para modales altamente estructurados.

6.3. Event Bus y Escuchas (Comunicación JS ↔ PHP)

VectorLab NO UTILIZA peticiones AJAX crudas ($.ajax o fetch) manuales para enviar formularios. Todo se maneja a través del Bus de Eventos de Livewire mediante los atributos #[On('nombreEvento')].

El flujo estándar de comunicación es:

  1. Usuario llena campos en un modal de SweetAlert (JS).
  2. La función preConfirm en JS captura los valores del DOM (`document.getElementById()`).
  3. El JS dispara: Livewire.dispatch('guardarProducto', [valoresEnJavascript]).
  4. El PHP atrapa el evento en el método anotado y lo inserta a la Base de Datos.
  5. El PHP responde al JS disparando un aviso: $this->dispatch('swal:success', ['título' => 'Éxito']).

Ejemplo Fidedigno de Código Backend

// EJEMPLO CORE: Recepción de Surtido de Stock desde public/js/inventario.js
#[On('actualizarStock')]
public function actualizarStock($id, $piezasAgregadas, $tipo)
{
    // 1. Encuentra el modelo mediante ORM Eloquent
    $producto = Producto::find($id);
    
    // 2. Modifica el registro contable en RAM
    $producto->stock += $piezasAgregadas;
    
    // 3. Persiste (COMMIT) a la base de datos SQL
    $producto->save();
    
    // 4. Callback para disparar la palomita verde de SweetAlert en el navegador
    $this->dispatch('swal:success', [
        'title' => 'Éxito',
        'text' => 'El stock ha sido sumado al inventario general.'
    ]);
    
    // IMPORTANTE: Al finalizar este método, Livewire recarga automáticamente 
    // la tabla HTML en el cliente, mostrando el nuevo stock instantáneamente.
}

6.5. Árbol y Mapa de Archivos Fuente del Módulo

Para cualquier modificación, soporte técnico o ampliación, refiérase a esta estructura exacta:

  • app/Livewire/Inventario.php : El Controlador Controlador principal. Contiene todas las consultas DB, los Listeners y la inicialización de estado.
  • resources/views/livewire/inventario.blade.php : La Vista (View). Tabla HTML, Layout, directivas de paginación e inyección de eventos globales.
  • public/js/inventario.js : La Lógica de Interfaz. Generación de strings de HTML para SweetAlert2, manejo del DOM, atajos de teclado y envío de datos (Livewire.dispatch()).
  • public/js/proveedores.js : Lógica compartida inyectada al módulo. Provee la función `nuevoProveedor()` que permite dar de alta contactos desde la misma vista del inventario.
  • app/Models/Producto.php : El Modelo de Datos. Define la tabla en DB (`productos`) y sus relaciones Eloquent (`belongsTo(Categoria::class)`).
